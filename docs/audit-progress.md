# پیگیری مرحله‌ای بررسی GeoBox

تاریخ: ۲۰۲۶-۱۱-۰۳

مبنای کار: گزارش ارسالی کاربر. فایل اصلی RFP و داده‌های واقعی در این مرحله بررسی نشده‌اند؛ وضعیت‌ها تأیید انطباق کامل با RFP نیستند.

## محدودیت‌های قطعی

- کلیدها، مقادیر و فایل‌های env تغییر نمی‌کنند.
- کد بک‌اند، BFF و تغییر قرارداد احراز هویت اضافه نمی‌شود.
- معماری فعلی و قابلیت‌های موجود با اصلاحات محدود حفظ می‌شوند.

## مرحله اول: پایداری اتصال، بارگذاری لایه و منابع نقشه

| مورد | اقدام و وضعیت |
| --- | --- |
| P1-01 احراز هویت | آزاد شدن قفل درخواست توکن در خطای JSON یا تنظیمات ناموجود؛ حفظ کش و دریافت مشترک توکن؛ افزودن تایم‌اوت. انتقال اطلاعات ورود به سرور انجام نشده و معیار مخفی‌بودن اطلاعات ورود در خروجی فرانت حل نشده است. |
| P1-02 API | کنترل لغو پیش از احراز هویت، پس از آن و هنگام خواندن پاسخ؛ یک بار تلاش مجدد برای 401؛ حفظ کد وضعیت و پیام قابل نمایش برای 403، 429 و 5xx؛ عدم تلاش مجدد روی خطاهای دائمی دریافت عوارض. |
| P1-02 صفحه‌بندی | حفظ پارامترهای API موجود؛ اعلام خطا هنگام رسیدن به سقف به جای ارائه نتیجه ظاهراً کامل؛ کنارگذاشتن صفحات پیش‌دریافت‌شده پس از اولین صفحه کوتاه؛ تطبیق با رفتار API واقعی هنوز لازم است. سقف فعلی عوارض ۵۰ صفحه × ۲۰۰۰ رکورد است. |
| P1-03 چرخه عمر | لغو فریم‌های زمان‌بندی‌شده رندر و هایلایت هر دو موتور نقشه؛ لغو بارگذاری لایه‌ها و محاسبات رابطه مکانی هنگام خروج از scope. بررسی تعاملی همه ابزارهای نقشه باقی است. |
| P1-04 هماهنگی وضعیت | جلوگیری از بازگشت لایه حذف‌شده، تقدم آخرین انتخاب دسته‌ای، جلوگیری از بازگشت اطلاعات پس از پاک‌سازی و حفظ نشانگر بارگذاری هنگام درخواست‌های همزمان. |
| P5 پیش‌نیاز تست | تست با runner داخلی Node و داده ساختگی؛ بدون نصب وابستگی یا اتصال به API واقعی. |

## معیار پذیرش و روش بررسی

- ورودی: درخواست‌های همزمان، پاسخ دیرهنگام، پاسخ نامعتبر، لغو و وضعیت‌های خطای HTTP.
- خروجی: نتیجه فقط برای انتخاب معتبر فعلی؛ خطای قابل نمایش بدون پاک‌شدن شرط‌های قبلی؛ آزادشدن نشانگر بارگذاری پس از اتمام کارهای جاری.
- فایل‌های مؤثر: `useGeoboxApi.js`، `useWellQuery.js` و cleanup دو کامپوننت نقشه.
- تست‌های بازگشت: `npm test`؛ شامل توکن، خطاهای HTTP، صفحه‌بندی، حذف/پاک‌سازی/تعویض لایه، بارگذاری همزمان و خروج از scope.
- بررسی ساخت: `npm run build`.
- اجرای موفق تست و build، جای بررسی تعاملی مرورگر و تأیید سرویس واقعی را نمی‌گیرد.

نتیجه اجرای این مرحله: هر ۲۵ تست موفق، ساخت production موفق و `git diff --check` بدون خطا بود. هشدار قبلی بزرگی بسته Mapbox در build همچنان وجود دارد. هیچ فایل env یا تنظیمات بک‌اند تغییر نکرد.

## مرحله دوم: چرخه عمر ابزارهای نقشه و هماهنگی پیش‌نمایش

- پس از خروج از کامپوننت، نتیجه ایمپورت دیرهنگام Mapbox دیگر نقشه ایجاد نمی‌کند.
- بارگذاری تنبل Draw مشترک است و فقط آخرین ابزار انتخاب‌شده اجازه ایجاد کنترل دارد. لغو ابزار، ورود به حالت انتخاب و خروج از صفحه، درخواست قبلی را بی‌اعتبار می‌کنند.
- حالت ترسیم پس از آماده‌شدن کنترل اعمال می‌شود؛ هنگام آماده‌نبودن استایل، انتظار قابل‌لغو تا رویداد idle برقرار می‌شود. خطای بارگذاری ابزار با پیام فارسی و بازنشانی حالت فعال مدیریت می‌شود.
- همه فریم‌های رندر، هایلایت، مختصات موس و تغییر حالت ترسیم به چرخه عمر همان نقشه متصل‌اند و هنگام خروج لغو می‌شوند.
- تغییر تم از وضعیت فعلی ابزار استفاده می‌کند؛ ابزار غیرفعال‌شده را برنمی‌گرداند. تعویض‌های پیاپی تم، callback بازیابی تکراری باقی نمی‌گذارند. تمی که حین بارگذاری Mapbox تغییر کرده نیز در ساخت نقشه لحاظ می‌شود.
- هندلرهای اختصاصی لایه‌ها پیش از تعویض استایل یا حذف لایه‌های نقشه جدا می‌شوند؛ با بازسازی استایل، هندلر کلیک/ورود/خروج موس تکثیر نمی‌شود.
- مارکرهای برچسب اندازه‌گیری با متد remove پاک می‌شوند؛ حذف صرفاً عنصر HTML کنار گذاشته شد. پاپ‌آپ اطلاعات قبلی هنگام بازشدن پاپ‌آپ بعدی یا خروج از نقشه بسته می‌شود.
- ابزار اطلاعات برای نقاط بدون هندسه، پاپ‌آپ را با API خود Mapbox باز می‌کند. تغییر رنگ پیش‌نمایش این نقاط حتی با ثابت‌بودن کلید داده، رندر تازه ایجاد می‌کند.
- هندلر تب پاپ‌آپ در Leaflet نیز هنگام خروج از کامپوننت جدا و مراجع نقشه/عارضه‌ها آزاد می‌شوند.

معیار پذیرش: خروج حین بارگذاری هیچ نقشه یا کنترل جدیدی ایجاد نکند؛ تغییر سریع ابزار فقط آخرین حالت را نگه دارد؛ غیرفعال‌سازی ابزار در میانه تغییر تم پایدار بماند؛ رویدادها و مارکرهای موقت پس از پایان استفاده باقی نمانند؛ پیش‌نمایش مارکری با تغییر ورودی تازه شود.

تست‌ها از سورس واقعی `MapboxMap.vue` کامپایل می‌شوند و با renderer آزمایشی Vue، موتور نقشه ساختگی و بارگذاری تأخیردار اجرا می‌شوند. این تست‌ها رفتار WebGL یا شبکه واقعی را تأیید نمی‌کنند. وابستگی جدید، تغییر env یا کد بک‌اند اضافه نشده است.

بررسی تعاملی Chrome در این مرحله انجام نشد: کنترل Chrome پس از تلاش مجدد هم متصل نبود و بررسی نصب، افزونه و native host فعال GapGPT را پیدا نکرد. برای ادامه بررسی مرورگر باید اتصال از Settings → Computer use → Google Chrome برقرار شود. صفحه‌بندی با GeoBox واقعی همچنان تأیید نشده است.

نتیجه مرحله دوم: ۱۷ تست جدید نقشه و ۲۵ تست مرحله قبل، در مجموع ۴۲ تست موفق؛ build نهایی موفق و `git diff --check` بدون خطا. هشدار قبلی اندازه بسته Mapbox باقی است. مرحله بعدی قابل انجام بدون سرویس واقعی، بررسی صحت Query توصیفی/مکانی با داده مرجع و سپس محاسبات چینه‌شناسی و CRS است.

## مرحله سوم ـ بررسی اولیه صحت کوئری (۳ نوامبر ۲۰۲۶)

اتصال Chrome برقرار شد. در اجرای واقعی برنامه، دو لایه با ۲۴ و ۷۴ عارضه مشاهده شد؛ فعال‌سازی و لغو ابزار خط و تغییر شمارنده پیش‌نمایش شرط `OBJECTID > 2000` به صفر بررسی شد. ورودی شرط پس از آزمون به حالت خالی بازگردانده شد. پس از تغییرات، فرم دوباره ۲۴ از ۲۴ نتیجه نشان داد و در بررسی کنسول خطای ثبت‌شده‌ای مشاهده نشد. این بررسی محدود، تأیید کامل چرخه عمر WebGL یا صفحه‌بندی سرویس واقعی نیست.

- محدوده انتخاب‌شده با انتخاب خالی، در پیش‌نمایش و محاسبه خروجی صفر رکورد برمی‌گرداند.
- کش شمارنده، هویت مجموعه انتخاب و آرایه داده را نیز بررسی می‌کند؛ تعویض انتخاب‌های هم‌تعداد نتیجه قدیمی را نگه نمی‌دارد.
- پیش‌فیلتر شعاعی بر پایه همان کره مورد استفاده در محاسبه فاصله تنظیم شد؛ عبور از نصف‌النهار ۱۸۰ درجه و رسیدن محدوده به قطب لحاظ می‌شود.
- مختصات خالی، null و خارج از محدوده در جست‌وجوی شعاعی، تبدیل ردیف به عارضه و خروجی GeoJSON به نقطه صفر تبدیل نمی‌شوند. مقدار عددی صفر و رشته عددی معتبر همچنان پذیرفته می‌شوند.
- مقدار میانی هاورساین برای جلوگیری از خطای گردکردن در فاصله‌های نزدیک نقطه مقابل، به بازه معتبر محدود شد.

شش تست مرجع اضافه شد؛ مجموع ۴۸ تست موفق است. بررسی جامع عملگرهای رابطه‌ای، تاریخچه انتخاب‌ها، لغو محاسبات مکانی و محاسبات چینه‌شناسی/CRS هنوز باقی است. env، وابستگی‌ها و بک‌اند تغییر نکرده‌اند.

## ترتیب ادامه گزارش

1. تکمیل بررسی تعاملی چرخه عمر نقشه و تطبیق صفحه‌بندی با سرویس واقعی.
2. بررسی صحت Attribute/Spatial Query، محاسبات Correlation Chart و CRS با نمونه‌های مرجع.
3. توسعه قابلیت‌های فرانت موردنیاز Contour و Thematic پس از تعریف ورودی و معیار صحت.
4. تکمیل خروجی‌ها، چاپ، دسترس‌پذیری و واکنش‌گرایی با تست مرتبط.
5. بازآرایی تدریجی کامپوننت‌ها پس از تثبیت رفتار فعلی.

آرشیو سازمانی، RBAC، نسخه‌بندی سمت سرور و انتقال credentialها به بک‌اند در محدودیت فعلی پیاده‌سازی نمی‌شوند. سند ارسالی تعریف دقیق کافی برای تأیید همه قابلیت‌های تخصصی RFP ندارد.
